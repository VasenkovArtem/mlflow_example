# Анализ экспериментов коллеги от Никулин К.А. по результатам Баженова (experiment `homework_Bazhenov`)

**Автор экспериментов:** Bazhenov (пользователь MLflow: student8)  
**Датасет / pipeline:** `adult-census-income`  
**Модель во всех успешных run:** логистическая регрессия (L2, `lbfgs`, `max_iter=1000`, при необходимости разный `model_C`).

В таблице экспорта колонка **`experiment_type`** задаёт **разрез** (что меняли в серии). Успешных run с метриками: **не менее 7** (один run `vary_train_size` завершился с **FAILED** — без метрик).

---

## 1. Разрез `vary_train_size` (размер обучающей выборки)

**Что фиксировано:** 6 признаков `race, sex, native.country, occupation, education, capital.gain`, `model_C=1.0`.  
**Что меняется:** `data_train_size_actual` / `data_train_size_param`: 2000 → 4000 → 6000 → 8000 (run на 1000 — падение пайплайна).

| Run name | train_size | ROC-AUC | PR-AUC | F1 |
|----------|------------|---------|--------|-----|
| nebulous-sponge-147 | 2000 | 0.7233 | 0.5187 | 0.3311 |
| wistful-dolphin-16 | 4000 | 0.7245 | 0.5191 | 0.3291 |
| whimsical-hen-398 | 6000 | 0.7273 | 0.5220 | 0.3286 |
| bald-gnu-564 | 8000 | **0.7278** | **0.5221** | 0.3288 |

**Вывод:** при росте train с 2000 до 8000 ROC-AUC и PR-AUC монотонно растут; наибольший скачок — с 2000 к 4000–6000, дальше прирост меньше.

---

## 2. Разрез `vary_C` (регуляризация, коэффициент C)

**Фиксировано:** те же 6 признаков, train **6000**, остальные гиперпараметры LR без изменений.  
**Меняется:** `model_C` ∈ {0.1, 0.5, 1.0}.

| Run name | C | ROC-AUC | PR-AUC |
|----------|---|---------|--------|
| dashing-dove-120 | 0.1 | 0.7269 | 0.5212 |
| invincible-moth-665 | 0.5 | 0.7272 | 0.5219 |
| mysterious-eel-473 | 1.0 | 0.7273 | 0.5220 |

**Вывод:** в узкой сетке по C метрики почти не различаются; оптимум около C=1.0 на доли тысячных.

---

## 3. Разрез `vary_features` (набор признаков)

**Фиксировано:** train **6000**, LR с C=1.0 (кроме случаев, где явно совпадают метрики с другими сериями).  
**Меняется:** список признаков и число категориальных/числовых (`data_cat_features`, `data_num_features`).

Примеры:

| Run name | Кратко про признаки | ROC-AUC | F1 |
|----------|---------------------|---------|-----|
| efficient-foal-146 | 6 фич (как база) | 0.7273 | 0.329 |
| omniscient-loon-144 | другой набор (education, capital.gain/loss и др.) | **0.8099** | **0.419** |
| ambitious-kit-210 / др. | расширенный набор (8 имён полей, 5 cat + 3 num) | **~0.826** | **~0.496** |

**Вывод:** смена набора признаков сильнее влияет на качество, чем сетка по C при фиксированных фичах; лучшие run — с расширенным набором (age, education.num, hours, marital.status, occupation, relationship, sex, native.country).

---

## 4. Разрезы `vary_model_c`, `vary_train_size` (дубликаты по метрикам)

Часть run (`bedecked-shrike-403`, `selective-wren-827`, `bald-vole-644` и т.д.) даёт **те же или почти те же** метрики, что и соседние — вероятно, повторный прогон с теми же параметрами или пересечение настроек между тегами `experiment_type`. Для выводов опираемся на серии, где параметр разреза однозначно меняется (таблицы выше).

---

## 5. Неуспешный run

**bouncy-foal-674** (`vary_train_size`, train 1000) — **FAILED**, метрик нет. Возможные причины: слишком малый train, ошибка в данных/пайплайне на этом размере.

---

## Сводка

| Разрез (логика) | Что варьировалось | Главный вывод |
|-----------------|-------------------|---------------|
| vary_train_size | 2000–8000 строк | Рост train улучшает ROC-AUC до ~плато у 6000–8000. |
| vary_C | 0.1, 0.5, 1.0 | Слабая чувствительность метрик к C. |
| vary_features | подмножества признаков | Сильный эффект; лучшие результаты у расширенного набора признаков. |
