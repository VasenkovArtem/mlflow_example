## Solver логистической регрессии
__Гипотеза__: выбор solver влияет на сходимость модели и ее итоговое качество
Изменялся параметр solver по следующим значениям: lgbfs, saga, liblinear.
![График solver](https://github.com/SevaErshov/mlflow_homework/blob/ershov/artifacts/roc_auc_solver.png)

Действительно, разные solver в результате давали разное качество на тестовой выборке (метрика ROC-AUC). Лучшим оказался liblinear, худшим - saga.

## Тип модели
__Гипотеза__: сложные модели, улавливающие нелинейные зависимости, покажут наилучшее качество предсказания
Перебирались следующие модели: логистическая регрессия, дерево решений, random forest, градиентный бустинг на деревьях.
![График модели](https://github.com/SevaErshov/mlflow_homework/blob/ershov/artifacts/roc_auc_model.png)

Вывод: худшее качество показала наипростейшая линейная модель (логистическая регрессия). По мере продвинутости и сложности моделей растет качество на тестовой выборке. Наибольшие значения ROC-AUC дают random forest и градиентный бустинг.

## Количество базовых моделей
__Гипотеза__: увеличение числа базовых моделей в градиентном бустинге приводит к росту качества (однако при большом количестве возможно переобучение)
Зафиксировал у коллеги тип модели в mlflow ui (градиентный бустинг) и далее перебирались следующие значения n_estimators: 200, 300, 400.
![График количество](https://github.com/SevaErshov/mlflow_homework/blob/ershov/artifacts/roc_auc_n_estimators.png)

В данной задаче такая сетка значений не сильно влияет на итоговое качество предсказания.
